五项长训练分别在 tmux（可断线恢复终端）会话中运行，带原生 PhysX（物理仿真引擎）日志监督。检测到会遗漏物理交互或设备错误时停止相应训练，不根据功率或任务曲线临时更改预算。不同 GPU 型号和运行条件会影响吞吐与数值轨迹，不宣称逐位轨迹一致；共同种子、配置和初始模型会核对。

本轮是实际固定预算训练，会产生新的 Stage3 权重。现有 Stage1/2 模型和奖励实现不变。新增种子参数用于可追溯性及后续复验；本轮仍统一使用种子 0。

## 独立验证分布

计划文件：[预算搜索独立验证样本](gpt-Stage3-预算搜索独立验证样本-v1.csv)。

- 沿用既有最终评估的五类地形、0–9 难度行、站立/低速/正常移动指令分层和指令向量分配。
- 验证种子为 210000、210001、210002；每个地形×难度×指令层×种子取 8 个回合。主样本共 3600 个回合；平地另列 72 个，总计 3672 个、51 组。
- 样本编号在原对应编号上加 1000000，避免复用原最终测试的随机流；地形与命令字段保持原设计，五个预算及两个基线复用这套独立验证表。
- 确定性策略均值、经验归一化冻结；每个样本只取首次回合，最长 2001 步，即 20.01 秒，包含终止步。失败回合不被后续重置补齐，超时与基座接触同时发生按失败处理。
- 每条轨迹同时计算任务指标和有符号完整修正功率，不拼接不同回放的字段。完整修正功率依旧用总代价除以总仿真时间，任务指标按平衡样本等权聚合。
- Stage1/2 基线也重新执行此验证，不能直接用原最终评估的均值替代。它们的原正式结果保持原样。
- 预算筛选不用现有 200000–200002 最终评估随机种子反复试参；候选确定后仍须执行原最终评估计划。

## 本轮候选筛选规则

在候选训练开始前，已向用户提出可选偏好问题。未收到不同偏好时，按先前说明的建议容差实施：以 Stage2 的独立验证结果为参照，联合成功率下降不超过 2 个百分点，生存率下降不超过 1 个百分点，线速度与偏航 RMSE（均方根误差）各自增幅不超过 10%。这些是本轮明确记录的工程比较选择，不声称为原论文标准或用户逐项指定。

同时要求完整修正功率点估计不超过 B，并保留既有联合成功率至少 80%、生存率至少 90%的操作性底线。所有地形×难度×指令层结果及相对 Stage2 的差值完整输出，不用总体结果掩盖困难地形损失。

自动输出仅为“单训练种子的点估计候选”，不会将最小候选写成最终 B。边界候选须补充独立训练种子，预算附近和任务容差附近的不确定结果须复验；还要审阅困难地形退化。后续若用户调整筛选偏好，记录调整时点，不改训练奖励，也不把事后标准称为事前标准。

## 执行入口与监测

- `src/pace_stage1/stage3_formal.py`：以明确瓦数启动正式训练，使用共享且已测试的运行循环。
- `src/pace_stage1/stage3_search_protocol.py`：固定验证样本与候选筛选规则。
- `src/pace_stage1/stage3_search_evaluation.py`：首次回合任务与功率联合评估，每组原生日志审核。
- `src/pace_stage1/stage3_search_watch.py`：汇总训练进度，依次验证两个基线，等待候选完整训练及原生监督结束后自动验证，生成预算对照表。

运行根目录：`artifacts/stage3-budget-search/gpt-local-linear-v1`。`gpt-搜索配置.json` 保存准确命令和路径；`gpt-搜索进度.json` 汇总五组最新更新、功率、乘子及验证进度；完成后输出 `gpt-预算对照结果.json` 和 `gpt-预算对照结果.md`。

每个训练的单行命令形如：

```bash
CUDA_VISIBLE_DEVICES=0 PYTHONPATH=src /home/xy.chen/miniconda3/bin/conda run --no-capture-output -n bruce_gym python -u -m pace_stage1.stage3_formal --output artifacts/stage3-budget-search/gpt-local-linear-v1/training/gpt-B100-seed0 --budget-w 100 --seed 0
```

实际长训练由独立 tmux 会话承载，原生监督日志保存在训练目录旁。正式恢复需要相同预算、种子、环境数及正式分类，拒绝将工程短训伪装成正式续训。
